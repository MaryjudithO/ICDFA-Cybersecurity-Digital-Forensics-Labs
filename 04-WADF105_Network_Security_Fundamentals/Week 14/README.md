# Lab 2: Web Application Security Testing

## Overview

This lab focused on web application security testing using DVWA (Damn Vulnerable Web Application) and OWASP Mutillidae within an authorised training environment. The objective was to understand how web applications process requests, validate file uploads, expose resources, and handle user input.

## Objectives

- Analyse HTTP requests and responses.
- Inspect web traffic using Browser Developer Tools and Burp Suite.
- Assess file upload functionality in DVWA.
- Examine extension and MIME type validation.
- Perform web server assessment using Nikto.
- Conduct content discovery using DIRB.
- Identify user-controlled inputs in Mutillidae.
- Observe SQL injection behaviour.
- Verify findings using SQLMap.
- Recommend defensive security controls.

## Tools Used

- Firefox Developer Tools
- Burp Suite Community Edition
- Nikto
- DIRB
- SQLMap
- DVWA
- OWASP Mutillidae

## Key Activities

### DVWA
- Set security level to Low.
- Intercepted HTTP requests using Burp Suite.
- Uploaded a harmless text file.
- Examined file upload validation and storage.

### Web Assessment
- Performed server assessment using Nikto.
- Conducted directory discovery using DIRB.
- Identified accessible application resources.

### Mutillidae
- Identified user-controlled parameters.
- Established baseline application behaviour.
- Performed manual SQL injection testing.
- Observed SQL syntax errors generated by unsanitised input.
- Reviewed automated verification concepts using SQLMap.

## Key Findings

- HTTP requests and cookies can be inspected using browser tools and Burp Suite.
- File extensions and MIME types should not be trusted for upload validation.
- Upload directories should not be executable or publicly exposed.
- Directory enumeration can reveal sensitive application resources.
- Unsanitised user input can lead to SQL injection vulnerabilities.
- Detailed database error messages expose internal application information.

## Defensive Recommendations

- Validate uploaded files server-side.
- Use allowlists for approved file types.
- Store uploads outside the web root.
- Use parameterised queries and prepared statements.
- Hide verbose database error messages.
- Apply least-privilege database permissions.
- Implement secure coding and input validation practices.

## Conclusion

The lab provided practical experience in web application security testing using DVWA and OWASP Mutillidae. The exercises demonstrated common web security weaknesses and reinforced the importance of secure file handling, input validation, proper error handling, and defence-in-depth security controls.
